# Seal note — reference format (from the writer, 2026-11-13)

Reference for Storyloom's "seal" step (the chapter note written when a chapter is finished). The writer
shared it as an example, not a requirement. Storyloom should adapt it: "her" / "the narrator" become the
story's own focus character and point of view; `canon/characters.md` / `canon/setting.md` become the
novel's character and place entries.

```
ch-NN — <the chapter's own title> (Day X)

## Summary
The day's shape in two sentences, ending where the page ends. 60 words max.

## What changed in her
Deltas only: what is new against the previous note. 90 words max.

## What the narrator now knows
The narrator's knowledge, and the places that reading was wrong, in the page's
terms. 60 words max.

## Must not drift
Page-specific facts a later chapter can contradict or must carry: times, standing
instructions, promises, objects left somewhere in a state, who was told what,
holes opened. Only these. 100 words max.

## Open threads
Bullets, eight max, twelve words each.

Contradiction: none | one line, only if the page conflicts with a sealed note.
```

## Do not include

- The sequence of events. That is `Summary`, two sentences.
- Traits the character entries already fix — hair, eyes, skin, build. Only page-specific specifics.
- Rooms and objects the setting entries already fix. Only ones the chapter changed state on.
- Dialogue verbatim beyond a six-word handle, and only for lines a later scene turns on: standing instructions, promises, a lie.
- A body inventory. Two or three page-specific details, not every description.
- Anything interpreted rather than read.
- Anything already in an earlier note, unless this chapter moved it.

## Rules

- Only what is on the page. Record the page's version and flag it if it fights an earlier note. Never silently choose, never repair canon.
- Be exact in `Must not drift`; that section is what later passes check against. Loose wording there becomes next chapter's contradiction.
- Re-sealing a chapter replaces that chapter's own note. Earlier notes are never touched.
- Ambiguity that survives is a bug; length that duplicates is a bug.

## Report — short

File written, word count, the day, open threads as a list, contradiction if any, then one line: the first
thing the next drafting pass needs.
